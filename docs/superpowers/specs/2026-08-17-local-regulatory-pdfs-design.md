# Локальные PDF нормативных документов — дизайн

## Цель

Сделать восемь нормативных документов доступными прямо с сайта как локальные PDF: основная кнопка открывает PDF без промежуточного перехода на сторонний сайт, отдельная кнопка скачивает тот же файл, а официальная публикация остаётся резервной ссылкой.

## Подготовка PDF

Пять RTF преобразуются локально в PDF штатным офисным конвертером без переписывания и сокращения текста. Для каждого результата проверяются:

- сигнатура `%PDF`;
- количество страниц;
- первая и последняя страницы;
- наличие номера, даты и названия акта;
- отсутствие обрезанного текста, пустых страниц из-за ошибки конвертации и повреждённых шрифтов.

Три исходных PDF не пересобираются без необходимости. Файлы № 1940 (112 147 804 байта, 698 страниц) и № 2188 (135 989 454 байта, 872 страницы) превышают лимит обычного файла GitHub 100 МБ. Они оптимизируются локально с сохранением всех страниц и читаемости; целевой размер каждого — не более 95 МБ. № 659 (4 162 290 байт, 18 страниц) копируется без изменения байтов.

Если любой из двух крупных PDF нельзя уменьшить до 95 МБ без заметного ухудшения текста или потери страниц, такой файл не публикуется в искажённом виде: работа останавливается для отдельного решения по хранилищу.

## Данные и действия карточек

Для каждого из восьми элементов в `src/data/documents.js` задаются:

- `href` — локальный PDF;
- `officialHref` — существующая официальная страница;
- `localPdf: true`.

Карточка нормативного документа выводит три действия в таком порядке:

1. `Открыть PDF` — локальный файл в текущем окне;
2. `Скачать PDF` — тот же файл с атрибутом `download`;
3. `Официальный источник` — резервная внешняя ссылка в новой вкладке с `rel="noopener"`.

Документы клиники без `officialHref` сохраняют два действия: открыть и скачать.

## Контроль целостности

Добавляется неизменяемый реестр локальных нормативных PDF с ожидаемыми публичными путями, размерами, SHA-256 и количеством страниц. Тесты проверяют:

- все восемь карточек связаны с правильными локальными путями;
- каждый файл существует и начинается с `%PDF`;
- размер и SHA-256 совпадают с реестром;
- локальное открытие, скачивание и официальный fallback имеют правильные подписи;
- в сборке нет отсутствующих или подменённых HTML-страницей PDF;
- исходные локальные документы клиники остаются без изменений.

## Адаптивность и доступность

Дополнительная третья ссылка не должна растягивать или обрезать карточки. Действия переносятся на следующую строку, сохраняют клавиатурный focus и остаются читаемыми при ширине 320 px и масштабе текста 200%. Новые внешние скрипты, трекеры, формы и зависимости в runtime не добавляются.

## Приёмка

- Восемь локальных PDF открываются из production preview с локального origin.
- PDF № 1940 содержит 698 страниц, № 2188 — 872, № 659 — 18.
- Первые и последние страницы всех файлов визуально проверены.
- На `documents.html` при 320 и 1280 px нет горизонтального overflow и обрезанных действий.
- `pnpm verify` проходит полностью, генерация повторяема, worktree чистый.
- После финальной проверки изменения отправляются в `origin/main` без force push.

## Границы

- Текст нормативных актов не редактируется и не пересказывается внутри PDF.
- Конвертация RTF не объявляется официальным опубликованием; карточка сохраняет ссылку на официальный источник.
- Оптимизация крупных PDF меняет бинарный хеш, но не количество и порядок страниц и не содержание документа.
- Git LFS, стороннее файловое хранилище и разбивка актов на части в эту реализацию не входят.
