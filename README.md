# Сайт ООО «Стоматология Ваша улыбка»

Многостраничный статический сайт стоматологической клиники. Проект собран на Vite и написан на обычных HTML, CSS и JavaScript без фронтенд-фреймворка. Исходные данные и контент превращаются в 21 HTML-страницу до запуска режима разработки или production-сборки.

## Требования и запуск

Нужны Node.js `^20.19.0 || >=22.12.0` и pnpm `11.16.0`. Требование Node.js совпадает с поддерживаемыми версиями текущей сборки Vite. После клонирования проекта:

```powershell
pnpm install
pnpm dev
```

Основные команды:

- `pnpm generate` — пересоздаёт HTML-страницы, `robots.txt` и `sitemap.xml` из исходных данных;
- `pnpm dev` — генерирует страницы и запускает Vite для разработки;
- `pnpm build` — генерирует страницы и собирает production-версию;
- `pnpm preview --host 127.0.0.1` — показывает собранную production-версию локально;
- `pnpm verify` — запускает все тесты, production-сборку и проверку готового сайта.

Готовый к размещению артефакт после `pnpm build` находится в каталоге `dist/`. На хостинг публикуется именно содержимое `dist/`, а не корень репозитория.

## Где обновлять данные и контент

- реквизиты, лицензия, адрес, телефоны и режим работы: `src/data/clinic.js`;
- услуги и будущий прейскурант: `src/data/services.js`;
- сотрудники и их квалификации: `src/data/staff.js`;
- источники правовой информации: `src/data/legal.js`;
- главная, общие, сервисные и правовые тексты страниц: `src/content/home-page.js`, `src/content/core-pages.js`, `src/content/service-pages.js`, `src/content/legal-pages.js`;
- состав страниц и их SEO-статус: `src/content/page-manifest.js`;
- общая HTML-разметка: `src/templates/render-page.js`;
- стили и интерактивное поведение: `src/styles/` и `src/js/`;
- иллюстративные hero-изображения, логотип, favicon и QR-изображение: `public/assets/`;
- копии исходных PDF-документов клиники: `public/documents/`.

После любых изменений данных или контента обязательно выполнить:

```powershell
pnpm generate
pnpm verify
```

Не редактируйте корневые `*.html` вручную: при следующей генерации они будут перезаписаны.

## Главная страница и визуальные материалы

- состав главной страницы: `src/content/home-page.js`;
- общий header и footer: `src/templates/site-chrome.js`;
- локальные SVG-иконки: `src/templates/icons.js`;
- превью предоставленных документов: `public/assets/documents/`;

Интерьерные изображения сопровождаются компактной подписью «Визуализация интерьера». После замены визуализаций реальными фотографиями клиники обновите подписи, проверьте права на публикацию и повторно выполните `pnpm verify`.

## Домен, sitemap и canonical

Реальный production-домен клиники пока не предоставлен. Поэтому сайт не содержит выдуманных canonical URL, а `sitemap.xml` до настройки домена остаётся без URL.

Переменная `SITE_ORIGIN=https://REAL-DOMAIN` — это обозначение поведения, а не готовый адрес. После получения реального HTTPS-домена нужно задать `SITE_ORIGIN` в среде сборки. Тогда команды `pnpm generate` и `pnpm build` добавят абсолютные URL в `sitemap.xml` и ссылку на sitemap в `robots.txt`. Скрипт отклоняет localhost, IP-адреса частных/тестовых диапазонов и служебные домены-заглушки.

Ниже только синтаксический шаблон; его нельзя запускать буквально — замените значение на фактический адрес:

```powershell
$env:SITE_ORIGIN = 'https://<РЕАЛЬНЫЙ-ДОМЕН-КЛИНИКИ>'
pnpm build
```

После получения домена также нужно добавить проверенные canonical URL и полный адрес сайта в политику конфиденциальности и повторно запустить полную проверку.

## Запись на приём и интеграция с МИС 32top

`src/js/core/appointment-provider.js` подключает МИС 32top с идентификатором `144e96ac-dbc8-4f44-a6c2-e27f96a783a6`. Все действия записи сначала открывают диалог клиники с онлайн-записью и официальными телефонами; без JavaScript ссылка остаётся обычной `tel:`-ссылкой.

Внешний скрипт `https://book-app.32top.ru/widget.js` загружается лениво только после явного разрешения онлайн-записи и нажатия соответствующей кнопки. Виджет инициализируется без дополнительной плавающей кнопки. Поля пациента находятся внутри интерфейса 32top: код сайта клиники не читает и не сохраняет их. При ошибке остаются прямая ссылка на форму и телефонная запись.

Сайт не формирует и не отправляет SMS. Два текста уведомлений, переданные клиникой как прошедшие модерацию МегаФона, зафиксированы без нормализации в `src/data/mis-sms-templates.js`. Порядок их настройки в кабинете МИС и обязательная проверка тарификации описаны в `docs/operations/mis-sms-templates.md`.

## Приватность и внешние ресурсы

Сайт использует `localStorage` только для записей `cookie-consent` и `accessibility-preferences`. `cookie-consent` версии 2 хранит только логический выбор `onlineBooking`; `accessibility-preferences` версии 2 строго хранит только настройки отображения и логическое поле `speechAnnouncements`. Записи не хранят медицинские или контактные данные, текст произнесённых фраз или историю выполненных действий.

После явного включения голос даёт только короткие подтверждения изменения настроек через доступный локальный русский голос браузера. Он не читает страницу целиком. Сайт не загружает сторонние TTS-сервисы; сетевого fallback нет. Сброс настроек удаляет `accessibility-preferences` и возвращает безопасные значения по умолчанию; очистка данных сайта средствами браузера удаляет обе записи. Кнопка «Обычная версия сайта» сохраняет выбранные предпочтения. Нет аналитики, трекеров, пикселей, удалённых шрифтов или автоматических карт. Единственный разрешённый сторонний виджет — онлайн-запись 32top после согласия.

Любое изменение поставщика МИС или подключение аналитики, карт, чатов, внешних шрифтов либо других форм меняет фактическую модель обработки данных и требует повторной правовой и технической проверки до публикации.

## Контролируемо неполные разделы

Страницы `specialists.html` и `prices.html` помечены `noindex` и исключаются из наполненного `sitemap.xml`. Этот статус можно убрать только после того, как:

- клиника утвердит полный прейскурант для страницы цен;
- для каждого медицинского работника будут подтверждены образование, аккредитация/сертификат и стаж по специальности для страницы специалистов.

После обновления данных и `noindex` нужно выполнить `pnpm generate` и `pnpm verify`.

## Поиск по сайту

`pnpm generate` создаёт `public/search-index.json` из опубликованных страниц и подтверждённых структурированных данных. Поиск выполняется полностью в браузере: запросы не отправляются на сервер, не сохраняются в URL, cookies или web storage и не передаются аналитике.

Ключевые слова и синонимы редактируются в `src/data/search-keywords.js`. Неподтверждённые медицинские направления добавлять в индекс нельзя. После изменения страниц, услуг, сотрудников или ключевых слов выполните `pnpm verify`.

## Иллюстративные изображения

Hero-интерьеры созданы как визуализации и не являются фотографиями помещений клиники. Компактную подпись «Визуализация интерьера» нельзя удалять до замены изображений реальными фотографиями. Перед такой заменой нужно проверить права на публикацию и согласия изображённых лиц.
